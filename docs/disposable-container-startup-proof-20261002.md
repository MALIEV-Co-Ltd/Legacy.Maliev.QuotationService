## Prototype boundary

The initial test-local prototype was promoted to the narrow NEW test-infrastructure helper after root review. It accepts a resource factory, maximum3 total attempts and injectable token-aware100ms/200ms backoff. It retries only parsed DockerApiException HTTP500 with one string message, the exact ordered networking/external-connectivity prefix and TCP-listen/address-in-use suffix. Malformed/duplicate/non-string responses, trailing unrelated text, different status, permission errors, allocated-port variants, readiness timeout, cancellation and all application/EF failures do not qualify. Catch encloses startup only; EF migration/seeding/assertions remain outside.

Every failed attempt must dispose and independently verify removal before backoff or fresh allocation. Cancellation and cleanup failure stop fail-closed. Each Docker attempt has fresh name/run/attempt labels, dynamic allocation except a test-only deliberate occupied-port negative, loopback publication, no reuse, Redis7-alpine tmpfs16MiB. Precreate local endpoint inspection rejects ambient remote host/context. Successful ownership transfers to caller for cleanup. No global parallel disable, assertion retry, timeout easing, OS/sysctl changes, persistent adoption or production writes.

Scripted controls independently assert allocation/start/disposal/verification order, exact predicate negatives,3-attempt exhaustion, cancellation before allocation/during backoff/at startup, cleanup failure and unrelated timeout propagation. Actual Docker control first starts real owned Redis, then attempts an intentionally occupied host port. If Docker Desktop emits `port is already allocated`, it must remain a nonmatching negative with one attempt; do not broaden the predicate to simulate CI. If exact matching collision occurs, only the fresh random replacement may succeed. The running blocker stays owned/alive until explicit cleanup. Pure scripted state proof is not Docker/kernel or application acceptance.
