# Quotation durable operation receipt: active implementation ABI

GET `/quotations/{quotationId:int}/invoice-completion/operations/{operationId:guid}?invoiceId={invoiceId}`. Same current invoice-bound `X-Maliev-Quotation-Invoice-Capability`, canonical same-operation `Idempotency-Key`, original `X-Expected-Modified-Date`, and ordinary Accounting workload Bearer. Live critical `legacy.quotations.update` on `/quotations/{quotationId}`, independently signed Accounting-executor originating-employee proof, fresh direct employee IAM and Accounting financial readback remain mandatory. GET is read-only and emits Cache-Control:no-store before every action result, including malformed-authority/absent/dependency cases. Missing receipt404, tuple mismatch409, malformed storage/dependency503, invalid authority403. Successful readback200 does not imply Completed; caller must inspect State.

Exact PascalCase v1 response fields: ContractVersion(int1), OperationId(lowercaseD string), QuotationId/InvoiceId(positiveint), OriginIssuer, EmployeeSubject, RequesterSubject(service:legacy-intranet), ExecutorSubject(service:legacy-accounting), OriginalQuotationVersion(UTC O sevenfractiondigits Z), FinancialBinding(uppercase64SHA256), FinancialBindingVersion(invoice-creation-financial-v1), State(string), DecisionOrderVersion(UTC O Z), CompletedOrders(int), TotalOrders(int), ModifiedDate(UTC O Z, retained local quotation version).

States: QuotationCommitted (local link/admission committed, no full Order proof), OrdersPartial (finite checkpointed prefix/subset), OrdersConflict (downstream typed conflict), Completed (all frozen distinct linked Order IDs durably checkpointed, including zero orders). Only Completed acknowledges whole quotation/order completion. OrderIds are frozen at local admission; later relationship edits do not expand that operation. Receipt retention is independent of later quotation edits/deletion; no cross-service or source-column FK is introduced.

PUT existing decision with Accepted=true, EmployeeInitiated=true, exact InvoiceId, original version and capability invokes existing repository decision core with an explicit verified context. One local SaveChanges transaction inserts operation authority/frozen membership alongside quotation link, acceptance outcome and applicable metadata. One operation per quotation, unique operation ID. Same InvoiceId with no exact receipt is409, never inferred/adopted. Different issuer/actor/requester/executor/quote/invoice/originalversion/binding/frame conflicts. Freshly minted nonce/expiry does not change immutable authority, permitting renewal with the same original operation/source version.

Conditional two-minute lease permits one active order reconciler. Each successful order is checkpointed using the original DecisionOrderVersion key; completed orders are skipped on continuation. Caller cancellation/unknown downstream acknowledgement preserves earlier progress; retry converges through Order's owning idempotent transition with the same key. Exact claim release is bounded to five seconds on every exit; failed release leaves a finite persisted lease. Late old-owner checkpoint cannot overwrite a newer claim. Completed replay returns the original response JSON/counts/local quotation version with no Order calls, independent of subsequent quotation edits/deletion. Partial resume requires an existing accepted quotation with the same invoice and exact committed local ModifiedDate; later edit/deletion fails409 without Order calls while GET still exposes retained partial evidence. GET never claims, resumes or writes.

The writer/readback/migration and regressions are implemented in the isolated source draft; hosted build/native acceptance and actual producer join remain unverified. This is not an available deployed API. Accounting unknown-ack recovery must retain NeedsReconciliation unless this exact owning GET returns matching Completed. Partial states may drive explicit same-operation PUT resume with a current genuine employee remint. Do not use generic InvoiceId GET, acceptance outcome or DecisionOrderVersion alone. Actual Auth mint, Accounting committed financial rows, normal-host quoted recipient and both Order/Status database readbacks remain required. No local SDK/Docker/data/DDL/deployment or producer edits.

Capability transport is strict: Accounting internal validation consumes a RAW compact JWT; outgoing custom header on both Quotation decision PUT and owning GET must add exactly one literal `Bearer ` prefix. Quotation rejects RAW and double-prefixed values, with four normalHTTP source cases. Ordinary Authorization Bearer remains independent. No parser broadening.
