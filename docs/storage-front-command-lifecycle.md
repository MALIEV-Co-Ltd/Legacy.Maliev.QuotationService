# C# storage-front command ownership successor

This source proposal changes only BoundedOwnedCommand.cs and adds dedicated production-policy controls. It preserves RunAsync(string, IReadOnlyList<string>, int, CancellationToken), exact caller arguments and byte results, stdout maximum 1..2,097,152 bytes, stderr maximum 16,384 bytes, five-second work cancellation and an independent five-second cleanup cancellation budget. A serialized admission wait is independently bounded to five seconds. Cleanup EOF draining has the same per-stream cap; original results and drain buffers can coexist, so this is not an aggregate two-MiB memory claim. No command or private stderr is added to public output.

Custody is installed before allocating Process or attempting Start. The linked work token is checked immediately before attempted Start; this refuses cancellation observed during setup and does not claim atomic ordering against concurrent cancellation. The owner retains the original Process, original reader/wait tasks, streams and managed handles, Linux pidfd, metadata streams and cleanup cancellation sources. A live association checks the retained original child exit state before and after independent kernel-parent/start-ticks and native-start association, pidfd acquisition and fdinfo PID readback. Only pidfd_send_signal is used for termination. There is no Process.Kill, tree/group kill, numeric-PID signal, broad scan or arbitrary child adoption. A fast natural original exit requires actual retained exit and both EOFs and never requires a signal. Runtime-handle acquisition is inside the association catch: if the original exits between the first check and getter, only positively retained original exit permits the natural-exit path. Other acquisition failures remain failures.

Cleanup attempts stream capture, descriptor association/signal, original wait, reader cancellation, each reader settlement and bounded EOF drain independently. Awaiting a reader uses a finite wait; an unfinished original Task stays reachable and is never overlapped with a new drain. Cancellation or closing streams does not set either EOF flag. Handles are released only after the original child has exited, all original/drain/wait tasks are terminal and both actual reads returned EOF. Each closure is attempted once, with its original managed handle IsClosed observation where available; an uncertain close is not retried. This is managed-object/handle evidence, not a kernel FD census or proof against opaque close failures.

RunAsync preserves the original body exception and retains its exact private reference in the owner through quarantine/recovery. The module keeps that original cause as its sticky first failure if cleanup fails; retaining a cause does not itself poison a fully settled semantic refusal. Any cleanup error is retained privately and becomes a sticky module refusal; an unsettled owner stays in quarantine. RetryCleanupAsync makes a fresh serialized attempt using the same original objects. Even after recovery, a cleanup failure remains a refusal of new commands. A semantic CLI nonzero or bounded-output rejection that is fully exited, EOF-drained and released still throws its operation error, but does not become an ownership quarantine or poison later commands. There are at most two cleanup attempts: the initial five-second attempt and one fresh five-second recovery, with ten seconds of aggregate awaited cleanup budget. Automatic quarantine recovery on a later RunAsync consumes that same one recovery; it never births a replacement or resets the budget. At most nine metadata acquisitions (three per run/binding attempt) and 32 private cleanup failure entries are retained. Exhausting the source-limited attempt budget refuses instead of inventing settlement. This does not increase the five-second work budget and does not claim total command latency of five seconds. Synchronous native calls and proc open/Dispose have no interruptible wall-clock proof; five-second budgets bound the awaited operations, not arbitrary opaque runtime/syscall stalls.

Attempted Start without accessible exact association stays retained and refused; this does not solve every internal Process.Start allocation fault. An original child may be reaped while a descendant keeps a redirected pipe open; no descendant ownership is inferred and unresolved EOF remains quarantined. Module reachability lasts only while the parent lives. Parent death, cross-process recovery, escaped descendants, all-FD closure and arbitrary private-state tampering are unsupported. Linux proc visibility, glibc-exported pidfd_open/pidfd_send_signal, original-child runtime wait-state semantics and an exclusive owner are admission prerequisites, not observed native facts here.

The dedicated xUnit source exercises the production independent-attempt, closure, settlement, release, admission and metadata decision seams without launching children.
