# Registry failure evidence and retry decisions

The preload receipt retains bounded structured evidence for future failures. A Docker failure still has a captured-prefix hash, byte counts, capture limit, truncation flag and `rawDisclosed: false`. Its `safeProviderMetadata` contains only an allowlisted error code, an explicitly surfaced HTTP status, bounded numeric retry/reset values, or a canonical Retry-After HTTP date. CLI provenance is `captured-cli-stderr`; metadata HTTP provenance is `metadata-http-response`. Unknown values remain null. Reset units are not inferred and rate-limit nature remains unclassified.

Metadata HTTP failures retain the same safe fields in `metadataFailureDiagnostic` before propagating the original exception. Diagnostic extraction occurs within the unconditional response-close region. Extraction, diagnostic getter, receipt save and best-effort error annotation failures preserve the original HTTP error. CLI code recognition uses ASCII case matching; Unicode lookalikes remain unknown. The added fields exclude URLs, body text, free-form reasons, credentials, authentication headers, cookies, caller identity and request IDs. Existing exception logging is not redesigned by this change.

The existing metadata GET policy remains three attempts for HTTP 429, using a numeric Retry-After of at most ten seconds within the existing request/shared deadlines. HTTP dates are recorded but do not enable retries. Other statuses, excessive delays and exhausted deadlines fail closed. Docker daemon mutations remain single-attempt: recording evidence never triggers a pull, tag or removal retry.

Do not equate a rate-limit classification with a verified temporary throttle. [Amazon ECR Public quotas](https://docs.aws.amazon.com/AmazonECR/latest/public/public-service-quotas.html) distinguish request-rate quotas from a monthly unauthenticated data quota. Those general limits do not establish the failed job's authentication, quota scope, egress identity, reset time or cause. [ECR API throttling guidance](https://docs.aws.amazon.com/AmazonECR/latest/userguide/common-errors.html) also does not by itself authorize Docker CLI retries. No SDK retry settings, authentication, image pins or runner configuration change here.

An operator considering an authorized bounded retry must first establish settlement of the previous mutation or verified destruction of its exact ephemeral runner. CLI exit, an absent local tag, lease expiry and a later successful independent job do not establish that fact. Use a fresh finite job with unchanged image pins, existing admission checks and retained CLI custody. Consider observed provider retry/reset or quota evidence when available; a hard quota or authentication denial requires resolving that condition first. Unknown provider conditions must not be labeled transient.

The discarded raw stderr from an older failure cannot be reconstructed from its hash. Its absence is not an impossible permanent prerequisite for a future authorized retry: use independently established settlement and current admissible evidence. This source change neither supplies that authorization nor starts a retry. The genuine eight-host financial run and production database operations remain outside this diagnostic slice.

New controls reproduced the reviewed exception-custody and Unicode lookalike defects against the frozen prior proposal before correction. Mock HTTP and Docker controls verify safe serialization, response closure, primary exception identity despite extraction/getter/permanent-save and annotation failures, existing 429 backoff, legitimate ASCII code casing, no Docker mutation after a metadata failure, and one failed pull attempt retaining its unresolved intent. No live provider request, Docker process, C# build, PostgreSQL migration or financial execution was performed.

Metadata HTTP failures additionally retain `requestContext`: `imageAlias`, `hostname`, `requestStage`, and `localAttempt`. The alias is one of `postgres:18-alpine`, `redis:7-alpine`, or `ryuk:0.14.0`; hostnames are the declared public registry or `hub.docker.com`. Stages are `token`, `provenance`, `index`, or `manifest`. These values are joined to the actual request URL by exact matching against the committed approved image pins, including immutable index/manifest digests. The URL itself, token query, headers, credentials, body, free-form exception wording and caller identifiers are never added to this context. Decorated, substituted or unknown URLs keep alias, host and stage null.

`localAttempt` is the ordinal of this request's existing fetch loop (1 through 3), not an external API-call count, quota measurement or cross-request history. A context-extraction failure retains the primary HTTP error, existing safe metadata and unconditional response close; alias, host and stage remain null while the local attempt ordinal is retained. The CLI `safeProviderMetadata` shape is unchanged. This observability change does not resolve HTTP 429, establish a reset time or quota nature, add retries, change credentials/routes/pins, or discharge daemon/runner custody.
