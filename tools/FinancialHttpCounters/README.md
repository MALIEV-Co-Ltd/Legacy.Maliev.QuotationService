# Financial HTTP counter collector proposal

This is a standalone net10 helper proposal, with no issuer, service, frozen runtime17/semantic38, or source-owner edits. Nothing here has been compiled or run with a local SDK. Controlled and native witness projects are prepared but unexecuted. No counter is accepted until an exact-head hosted native witness and actual selected-host observation succeed.

The private collector input binds four actual held processes to the selected Accounting `ad45c78d7546674b5bb7eacff62759460df6ca02`, Document `af0976cbbb0fa9b2da41822f5d67e95b839f8a91`, File `d8be968eb73e7216568248af16a780057098be22`, and Notification `55c2c4b68bfd7749c9262929c850032be6df44e0` source objects. It checks the direct caller PID/kernel/native generation and executable/script, each target PID/parent/kernel/native generation, executable/DLL/runtimeconfig bytes, exact private environment hash, consumed Accounting `Services__Document`/`Services__File` values, actual mapped telemetry DLL bytes and net10 assembly versions, and clean Git heads/trees. The caller must create this manifest from its retained process/build/source receipts, never guessed PID/start/configuration values.

The input uses the exact C# `CollectorInput`, `ParentPin`, `ProcessPin`, and `FilePin` property names. It is mode0600 at a canonical absolute path outside public artifacts. `RequiredEnvironment` remains private and may contain synthetic configuration. `RuntimeLibraries` has exactly the actually mapped `System.Diagnostics.DiagnosticSource.dll` and `System.Net.Http.dll` paths/hashes. `DocumentOrigin` and `FileOrigin` are canonical HTTPS origins ending `/`. Production or provider credentials are not needed by the collector. Pass the private input path and one fresh public output path to the compiled helper; no raw configuration is placed in command arguments.

After four exact EventPipe sessions start, the helper prints `SessionsStarted=true` with observation completeness false. The caller then makes a real `GET /health` in each observed host, waits for collector admission, and sends only these ordered lines over its held private stdin pipe: `baseline`, `completion`, `replay`, `stop`. Each phase acknowledgement remains provisional. One second of caller quiescence follows each marker. Markers identify causal windows; they do not contain result/counter integers. Real events are timestamped inside their target runtimes and classified only after stopped, fully drained streams. A complete receipt requires positive runtime and actual hosting-schema canaries, known diagnostic schemas, balanced request start/stop identities, no boundary-crossing/near-boundary effects, EOF and zero reported event loss in every stream, and reobserved exact process/source generations.

The current single full-scenario producer CLI has no external completion/replay phase handoff. It cannot supply distinct internal windows merely by surrounding the whole CLI with markers. An owned runner adapter or sole-writer-reviewed producer handoff is required before this collector can satisfy its per-phase contract. Preserve source-owner boundaries when adding that handoff.

The helper enables only explicit DiagnosticSource projections. Outbound fields are method, scheme, host, port, absolute path and a private correlation ID; inbound fields are method/path/trace identifier. Stops project status and task state. Implicit projections, queries, headers, tokens, request/response bodies, exception strings, stacks and rundown are disabled. There are no trace files. Private payload bytes flow into a bounded parser; only named aggregate counts, process/source/hash receipts and loss/EOF observations are public. Four runtime buffers are 16MiB each; each stream has a 64MiB total-byte cap, pending requests are capped at1024 and diagnostic events at100000. Collection and control waits share a finite ten-minute maximum monotonic cancellation timer. Stop/drain and cleanup each have separate short bounded waits. Target application processes remain owned by their caller.

Each public owner snapshot contains explicit counter labels in `BeforeBaseline`, `Completion`, `Replay`, and `AfterReplayThroughDrain`. Accounting distinguishes POST `/Uploads` from its other methods and separates invoice/receipt render POSTs. Document and File counts are incoming HTTP boundaries; HTTP success alone does not prove PDF contents, quarantine, object promotion or metadata persistence. File incoming totals can include caller signature-preparation uploads; they are not asserted to be Accounting-only calls. Notification counts every HttpClient attempt to the fixed selected-source HTTPS Brevo origin, regardless of path/method. Zero observed provider HTTP attempts covers only the attached collection interval. It cannot prove that no startup/pre-attach send occurred, or that arbitrary socket, SMTP, native, alternate-handler or non-HttpClient code did not send. `SmtpNoSendProven`, `SocketNoSendProven`, and `GenuineEightHostFinancialAccepted` remain false in every receipt. The rest of the financial gates still require their actual independent evidence.

`controls` exercises method distinction, explicit replay zeros, public-output redaction, actual-request balance, phase-crossing and guard rejection, missing canaries, query exclusion, decoder schema rejection and trace-byte budget. `native-controls` launches one retained disposable `witness-host`, performs real HTTP POST/DELETE/replay operations and reads its real EventPipe stream to prove codec/schema/drain behavior. That witness explicitly leaves source admission, business schemas, SMTP/socket and financial acceptance false. It makes no external network/provider request, creates no database/container and kills only its retained synthetic child. Native witness output must be parsed as codec evidence, not as the real financial run.

On an authorized Ubuntu net10 runner, restore/build the projects, run `controls`, build `witness-host`, and run `native-controls` with the actual absolute dotnet executable and built witness-host DLL. The first hosted restore must generate and retain reviewed NuGet lockfiles; subsequent native runs require locked restore. Top-level versions are exact `Microsoft.Diagnostics.NETCore.Client`0.2.745401 and `Microsoft.Diagnostics.Tracing.TraceEvent`3.2.8. Transitive dependencies and compilation are unproved until that hosted gate. Do not report any prepared control count as a pass.

Only the actual complete stream's reported sequence loss and fail-closed completeness gates support a receipt.

Admission successor: a five-second monotonic cancellation deadline exists before private input opening. Non-proc files use the retained `DescriptorBoundFrontFile` component: component-bound `openat` with `O_NONBLOCK|O_NOFOLLOW`, regular-descriptor `statx`, byte bounds, cancellation-aware reads, and before/after/current-path identity equality. Input owner/0600 permissions are checked on that held descriptor. Pinned runtimeconfig and assembly metadata are parsed from the same checked bytes, avoiding a second pathname open. Typed kernel `/proc/PID/{stat,environ,cmdline,maps}` reads remain separate. The exact retained component copy and its source association are recorded in `descriptor-provenance.json`.

Output admission creates no file and retains no rejected path. The accepted output holds a nonredirected parent directory descriptor; final creation is relative to that descriptor with `O_CREAT|O_EXCL|O_NOFOLLOW`, checked parent identity, bounded bytes and a five-second write deadline. The Linux native witness now exercises an actual owned FIFO with no writer, `/dev/zero`, a directory, symlink/inode replacement after opening, descriptor private-mode rejection, pre-cancelled admission, redirected/refused output, replaced output parent, and positive output. These controls remain unexecuted until the exact-head Ubuntu witness.
