# Private c821 real-producer acceptance driver

This executable drives real normal Auth login/session creation, actual service login, original invoice-create delegation, Accounting financial prepare and owning readback, actual invoice-bound Auth issuance, Quotation's independent recipient/receipt writer and actual Order HTTP transitions. SQL readback uses the actual separate disposable Auth customer identity, Auth employee identity, Auth session, Payment, Invoice, Receipt, Quotation, QuotationRequest, Order, OrderStatus and IAM PostgreSQL18 databases. It supplies no fake financial writer, issuer, receipt store or Order transition response.

Root supplies the current accepted producer revisions and a privately owned healthy Production fixture profile. Do not substitute guessed SHA pins, launch against production, or treat this authored project as executed evidence. The driver fails unless every origin is HTTPS loopback, every database is loopback with a run-specific `c821_` name and PostgreSQL18, every source checkout is clean at the exact supplied commit/tree, and the fixture lease is current and finite. TLS must validate normally through the fixture's per-process trust configuration. No permissive certificate callback is installed.

The fixture profile contains only origins, source paths/revisions, finite run lease, synthetic seeded quotation/order IDs and a user-editable invoice intent with SendEmail=false. Credentials and disposable database strings are environment-only and never copied into output. Required environment names are listed in Program.cs. Auth/IAM grants, seeded customer/employee/currency API fixtures, actual service configuration and process ownership/cleanup belong to the root fixture launcher; this driver creates no servers, migrations, containers or port forwards and never stops supplied services.

The driver's scope is the real financial -> Auth-bound proof -> Quotation -> Order owning-receipt boundary. Accounting's final full completion/resume route, PDF/upload/notification phase and Intranet UI handoff remain separate owner integration requirements. The current Accounting owner has a prepare route and a production resume workflow, but its public full complete consumer is now authored and must be accepted by root before extending this driver; the driver does not invent that route or replace it with fake persistence. Controlled acknowledgement loss deliberately discards the received decision response body; only exact owning GET resolves it. SQL stability after replay proves no new persisted effects, not zero downstream HTTP requests by itself.

After exact full source review, build and execute this project only in the normal hosted Ubuntu lane with owner-supplied sources/profile. The profile and secrets are private runtime artifacts, excluded from Git. Successful output retains only hashes, source commits, aggregate assertions and finite resource cleanup metadata, never JWTs, passwords, DB strings, raw invoice/employee/customer rows or case arguments. Failure output is opaque and does not include exception messages.

Profile Sources has exactly Auth/Accounting/Quotation/Order/IAM entries with clean commit/tree, live PID/actual UTC start, absolute DLL path and uppercase SHA256, DatabaseBindings mapping each ConnectionStrings__ environment key to its required DB role, and ServiceBindings mapping Services__ keys to the owning origin role. The driver re-observes Linux process command/environment without logging them and checks source/DLL identity, Production environment, C821_FIXTURE_RUN_ID/C821_FIXTURE_EXPIRES_UTC, actual connection targets/credentials and Quotation critical outbound write/read/auth/IAM origins and fail-closed feature flags. Required DB roles are AUTH_CUSTOMER_IDENTITY,AUTH_EMPLOYEE_IDENTITY,AUTH_SESSIONS,PAYMENT,INVOICE,RECEIPT,QUOTATION,QUOTATION_REQUEST,ORDER,ORDER_STATUS,IAM. Exact consumed mappings are fixed in ProducerDatabaseBindings.cs from owning registration source; profile-supplied arbitrary keys cannot replace them. The live process must contain each exact key once, with matching host/port/database/user/password; colon/case aliases are rejected. The helper is compiled directly into native regression tests. Fixture launcher must provide all backend isolation/configuration and normal TLS trust before running; the driver never provisions or repairs those resources.

Before using any producer, all11 roles must have distinct physical PostgreSQL identities. Loopback host aliases are normalized; port and case-sensitive database name identify the backend. Usernames/passwords and raw connection-string spelling do not separate databases. Same server with different database names is valid, as are distinct ports. Native isolation controls are authored, not executed.

Fixture APIs must launch as dotnet plus exactly one absolute DLL path, without configuration arguments. Configuration belongs in the observed process environment. The admitted executable identity must also be dotnet. This excludes every normal command-line override spelling rather than attempting to recognize a subset of protected keys. Native launch controls are authored and unexecuted.
